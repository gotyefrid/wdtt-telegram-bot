# wdtt-telegram-bot — Документация проекта

## Назначение

Telegram-бот для управления клиентами двух типов: **WDTT** (`wdtt.service`,
`wdtt.py`) и **iPhone** (WireGuard-пиры в 3x-ui + `vk-turn-proxy-ios`, `xui.py`).
Тип выбирается при создании клиента; один человек с несколькими устройствами —
это несколько клиентов разных типов. Часть про WDTT: бот пишет
напрямую в `/etc/wdtt/passwords.json` (смонтирован в контейнер), вокруг каждой
записи/удаления останавливает и поднимает сервис по SSH. На каждого клиента
генерирует `wdtt://`-ссылку на `wdtt.service` (Android/WDTT-клиент, `wdtt.py`);
тот же формат ссылки понимает и iOS-приложение, отдельной ссылки для него не
требуется.

## Запуск

```bash
docker compose up -d --build   # сборка и запуск
docker compose restart         # перезапуск без пересборки
docker logs wdtt-telegram-bot        # логи
```

## Структура файлов

| Файл | Назначение |
|---|---|
| `bot.py` | Telegram-бот: хендлеры команд, колбэков, FSM-диалоги |
| `clients.py` | Общий слой над типами: клиент адресуется `ref` = `w:<пароль>` или `i:<email>`, функции `list_clients/get_client/add_client/…` вызывают `wdtt.py` или `xui.py` |
| `xui.py` | Клиенты iPhone через API 3x-ui (токен): создание/правка/удаление пира в WireGuard-входе, сборка `vkturnproxy://`-ссылки |
| `wdtt.py` | Прямая работа с `/etc/wdtt/passwords.json` + SSH-управление `wdtt.service` |
| `config.py` | Конфиг из переменных окружения |
| `.env` | Секреты и настройки (не в git) |
| `docker-compose.yml` | Сервис `wdtt-telegram-bot`: монтирует `.` в `/app` и `/etc/wdtt` в `/etc/wdtt` |
| `settings.json` | Переопределённый через бота домен/IP для ссылок и флаг отправки бекапов (не в git, создаётся автоматически). Если файла/ключа `public_domain` нет — используется `WDTT_PUBLIC_IP` из `.env`; если ключа `backups_enabled` нет — бекапы выключены по умолчанию |
| `secrets/wdtt_ssh_key` | Приватный ключ для forced-command SSH к хосту (не в git) |
| `backups/wdtt/` | Бэкапы `passwords.json` перед каждой записью (не в git). Хранится не больше `WDTT_MAX_BACKUPS` файлов — самый старый удаляется при создании нового |
| `scripts/setup-wdtt-ssh.sh` | Провижининг SSH-доступа к `wdtt.service` при разворачивании на новом сервере: создаёт пользователя `wdtt-ctl`, ключ, forced-command и sudo-правило. Запускать от root на хосте один раз, идемпотентен |
| `scripts/wdtt-ctl.sh` | Forced-command скрипт, на который указывает ключ из `setup-wdtt-ssh.sh`; разбирает `start`/`stop`/`status` и вызывает `systemctl` через `sudo` |

## Переменные окружения (.env)

| Переменная | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота |
| `ALLOWED_USERS` | Telegram user_id через запятую |
| `WDTT_CONFIG_DIR` | Путь к конфигу wdtt в контейнере (`/etc/wdtt`) |
| `WDTT_PUBLIC_IP` | Публичный IP/домен сервера, на котором запускается бот |
| `WDTT_SERVICE_NAME` | Имя systemd-юнита (`wdtt`) |
| `WDTT_PORTS` | Три порта `wdtt.service` через запятую, в том же порядке, что в `wdtt://`-ссылке (по умолчанию `56000,56001,9000`) |
| `WDTT_MAX_BACKUPS` | Сколько локальных файлов в `backups/wdtt/` хранить одновременно (по умолчанию `20`); при превышении удаляются самые старые |
| `XUI_BASE_URL` / `XUI_TOKEN` | Адрес панели 3x-ui вместе с base path (`https://домен:2053/<path>`) и API-токен (`x-ui setting -getApiToken` — **сбрасывает** прежний токен) |
| `XUI_INBOUND_ID` / `XUI_VERIFY_TLS` | ID WireGuard-входа (по умолчанию `3`) и проверка TLS панели (`0` — отключить) |
| `IOS_PEER_ADDRESS` / `IOS_DNS` / `IOS_NUM_CONNECTIONS` | Что попадает в ссылку iPhone: адрес `vk-turn-proxy-ios` (`домен:56100`), DNS, число соединений |
| `WDTT_SSH_HOST` / `WDTT_SSH_USER` / `WDTT_SSH_KEY_PATH` | SSH-доступ к хосту для start/stop/status сервиса. `WDTT_SSH_USER` — непривилегированный пользователь `wdtt-ctl`, создаётся `scripts/setup-wdtt-ssh.sh` |

### iPhone-клиенты (`xui.py`)

- Инфраструктура: сервис `vk-turn-proxy-ios` (UDP 56100, SRTP) → WireGuard-вход
  3x-ui (`XUI_INBOUND_ID`, порт 51820). Клиентов добавляет/правит бот через API
  панели; ключи и tunnel-IP панель выдаёт сама, xray при этом **не
  перезапускается**.
- VK-хеш клиента хранится в поле `comment` клиента в 3x-ui; срок — `expiryTime`;
  деактивация — `enable=false`. Имя клиента = email в 3x-ui (уникален во всей панели;
  макс. 32 символа), переименовать iPhone-клиента нельзя.
- Ссылка `vkturnproxy://import?data=…` собирается так же, как `quick_link.py`
  (публичный ключ входа считается из его секретного). **QR внешним сервисом не
  делается**: в ссылке приватный ключ WireGuard.
- Бекапы в Telegram касаются только файлов WDTT; состояние iPhone-клиентов живёт в
  БД 3x-ui (`/root/panel/db/x-ui.db`).
- Update в 3x-ui принимает запись клиента в другом формате, чем отдаёт GET
  (`id` — строка-uuid, `allowedIPs` — список): см. `xui._update`.

## Команды бота

| Команда | Описание |
|---|---|
| `/start` | Главное меню с инлайн-кнопками |
| `/cancel` | Отменить текущий FSM-диалог |

Список команд (`bot.BOT_COMMANDS`) регистрируется через `bot.set_my_commands`
при каждом запуске бота (в `main()`), поэтому меню команд в Telegram
(кнопка "/") всегда соответствует коду, без ручной настройки через BotFather.

Основное взаимодействие — через инлайн-кнопки:

- **Создать клиента** → выбор типа (WDTT / iPhone) → диалог: имя → VK-хеш/ссылка → срок в днях → создаёт запись, возвращает `wdtt://`- или `vkturnproxy://`-ссылку
- **Список клиентов** → кнопки по 2 в ряд, с иконкой типа (🤖 WDTT, 📱 iPhone), имя или `AAAA...ZZZZ`, если имя не задано; если один из источников недоступен, под заголовком показывается предупреждение, а клиенты второго типа всё равно выводятся → карточка клиента
- **Получить ссылку** → без диалога ссылка, если VK-хеш уже сохранён; иначе один раз спрашивает и сохраняет
- **Редактировать** → подменю из карточки клиента с четырьмя пунктами:
  - **Переименовать** → диалог: новое имя → `wdtt.set_name`
  - **VK-хеш** → диалог: новый VK-хеш/ссылка (та же валидация, что при создании) → `wdtt.set_vk_hash`, перезаписывает уже сохранённый хеш
  - **Статус** → экран с текущим статусом и одной кнопкой-переключателем (Активировать/Деактивировать) → `wdtt.set_deactivated`; переключает только флаг `is_deactivated`, статус «истёк» не трогает (он вычисляется из `expires_at`)
  - **Срок** → диалог: число дней 1–365 (как при создании) → `wdtt.set_expires_days`, пересчитывает `expires_at` = текущее время + N дней (не прибавляет к старому сроку, а задаёт новый от текущего момента)
  - Все пункты после сохранения возвращают на карточку клиента
- **Удалить** → подтверждение → удаление записи + связанного устройства
- **Настройки** → доступно в любой момент из главного меню, вне диалога создания клиента:
  - **Изменить домен** → диалог: новый домен/IP → `wdtt.set_public_domain` (сохраняется в `settings.json`, подставляется во все новые ссылки вместо `WDTT_PUBLIC_IP`)
  - **Бекапы** → экран с описанием (бекапы шлются только в момент изменений, не по расписанию) и одной кнопкой-переключателем (Включить/Выключить) → `wdtt.set_backups_enabled`

В карточке клиента срок действия показывается с количеством оставшихся дней в
скобках, например `до 01.08.2026 12:00 (9 дн.)` (округление вверх, минимум 0).

После каждого создания/переименования/задания VK-хеша/удаления клиента бот
шлёт всем `ALLOWED_USERS` архив `passwords.json`+`names.json`+`settings.json`
(`bot.send_backup`, `wdtt.backup_archive`) беззвучным сообщением
(`disable_notification=True`) — бекап без отдельного крона. По умолчанию
отправка выключена; включить можно в **Настройки → Бекапы**
(`wdtt.get_backups_enabled`/`set_backups_enabled`, сохраняется в
`settings.json`); `send_backup` проверяет флаг перед отправкой.

## FSM-состояния

| Состояние | Что ждёт |
|---|---|
| `NewClient.waiting_name` → `.waiting_vk_hash` → `.waiting_days` | Имя → VK-хеш/ссылка → срок в днях (1–365) для нового клиента (тип сохранён в данных FSM как `kind`, ключ клиента в остальных состояниях — `ref`) |
| `GetLink.waiting_vk_hash` | VK-хеш для клиента, если он ещё не задан |
| `Rename.waiting_name` | Новое имя клиента (пункт «Переименовать» в меню «Редактировать») |
| `EditClient.waiting_vk_hash` | Новый VK-хеш/ссылка для уже существующего клиента (перезаписывает старый) |
| `EditClient.waiting_days` | Новый срок действия в днях (1–365) от текущего момента |
| `Settings.waiting_domain` | Новый домен/IP для ссылок |

## Валидация

- **Имя**: `re.sub(r"[^a-zA-Z0-9_-]", "", raw)` — всё лишнее удаляется; если результат пустой — ошибка
- **VK-хеш/ссылка**: не валидируется строго, принимается любая непустая строка

## wdtt.py — ключевые функции

```python
list_clients()                             # [{password, name, vk_hash, expires_at, is_deactivated, device_id, ip}, ...]
get_client(password)                       # детальная запись одного клиента
add_client(name, vk_hash, expires_days)    # создаёт запись, возвращает {password, vk_hash}
delete_client(password)                    # удаляет запись (+ связанное устройство), возвращает name
set_vk_hash(password, vk_hash)             # задаёт/перезаписывает VK-хеш
set_name(password, name)                   # задаёт/меняет имя клиента (используется и кнопкой "Переименовать")
set_deactivated(password, is_deactivated)  # переключает флаг is_deactivated (кнопка "Статус")
set_expires_days(password, expires_days)   # задаёт expires_at = сейчас + N дней (кнопка "Срок")
build_wdtt_link(password, vk_hash)         # wdtt://domain:56000:56001:9000:password:vk_hash
short_password(password)                   # "AAAA...ZZZZ" — заглушка вместо имени в списке
backup_archive()                           # (bytes, filename) — tar.gz из passwords.json+names.json+settings.json в памяти
get_public_domain()                        # домен/IP для ссылок: settings.json, иначе WDTT_PUBLIC_IP
set_public_domain(domain)                  # сохраняет домен/IP в settings.json
get_backups_enabled()                      # включена ли отправка бекапов (settings.json, по умолчанию False)
set_backups_enabled(enabled)               # включает/выключает отправку бекапов в settings.json
```

Мутирующие функции (`add_client`, `delete_client`, `set_vk_hash`,
`set_deactivated`, `set_expires_days`) оборачивают
изменение `passwords.json` в процедуру backup → SSH `stop` → запись файла →
SSH `start` → SSH `status`, т.к. сам сервис периодически перезаписывает файл
и может затереть параллельную правку. **Имена клиентов хранятся отдельно** —
в `/etc/wdtt/names.json`, а не в `passwords.json`: у Go-сервера в структуре
`PasswordEntry` нет поля `name`, и он стирает незнакомые поля при каждом
собственном сохранении (срабатывает при подключении клиента). `names.json`
сервис не трогает, поэтому `set_name`/`get_client` читают и пишут его
напрямую, без stop/start.

## Известные ограничения

- Лимит на число клиентов ограничен количеством доступных IP-адресов WireGuard (в отличие от `maxGeneratedPasswords=10` у встроенного self-service бота оригинального сервера — он на нашу логику не распространяется)
- Порты (`WDTT_PORTS`) и путь конфига (`WDTT_CONFIG_DIR`) настраиваются только через `.env`, диалогом бота — нет
